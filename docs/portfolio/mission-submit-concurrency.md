# 미션 인증 제출 동시성 정합성 보완

## 1. 문제 상황

미션 인증 제출 API는 "하루에 같은 미션을 한 번만 진행할 수 있다"는 제약이 있습니다.

초기 구현은 다음 순서로 동작했습니다.

1. 오늘 이미 제출한 미션이 있는지 조회한다.
2. 없으면 `mission_completions`에 `PENDING` 데이터를 저장한다.

이 방식은 단일 요청에서는 자연스럽게 보이지만, 같은 사용자가 거의 동시에 2번 요청하면 두 요청 모두 조회 시점에는 "아직 제출 이력이 없음"이라고 판단할 수 있습니다.

그 결과, 둘 다 저장에 성공하면서 같은 날 동일 미션에 대한 중복 `PENDING` 데이터가 생길 수 있었습니다.

## 2. 왜 문제였는가

이 문제는 단순 중복 저장이 아니라, 비즈니스 규칙이 깨지는 문제였습니다.

- 검수 대기 건이 2개 생길 수 있습니다.
- 운영자가 어떤 요청을 기준으로 검수해야 하는지 애매해집니다.
- 이후 보상 지급, 상태 변경, 이력 조회가 모두 꼬일 수 있습니다.

즉, "중복 제출 방지"는 서비스 로직의 편의 기능이 아니라 데이터 정합성 규칙으로 다뤄야 했습니다.

## 3. 선택한 해결 방식

이번에는 `users` row를 기준으로 비관적 락을 거는 방식으로 정리했습니다.

### 적용 방식

- `UserRepository.findByDeviceIdForUpdate(...)`를 추가했습니다.
- 미션 제출 시작 시 일반 조회 대신 `PESSIMISTIC_WRITE`로 사용자를 조회합니다.
- 같은 사용자의 동시 요청은 첫 번째 트랜잭션이 끝날 때까지 대기합니다.
- 뒤에 들어온 요청은 대기 후 다시 조회 로직을 수행하고, 이미 제출 건이 있으면 `MISSION_UNDER_REVIEW` 예외를 반환합니다.

## 4. 왜 이 방식을 선택했는가

### 선택 이유

- 지금 비즈니스 규칙의 기준이 "같은 사용자"이기 때문에 락 범위가 명확합니다.
- 구현 복잡도가 상대적으로 낮습니다.
- 애플리케이션 레벨 재시도보다 의도가 더 분명합니다.
- "한 명의 사용자가 동시에 같은 기능을 여러 번 누르는 상황"을 가장 직접적으로 막을 수 있습니다.

### 고려했던 다른 방법

#### 1) 서비스 조회 후 저장만 유지

가장 단순하지만, 현재처럼 race condition을 막지 못합니다.

#### 2) DB 유니크 제약으로만 방어

DB 레벨에서 강하게 막을 수 있다는 장점이 있습니다.
다만 이번 요구사항은 `REJECTED` 이후 같은 날 재제출 가능 여부까지 함께 고려해야 해서, 단순 유니크 키만으로는 표현이 까다롭습니다.
상태 조건이 들어간 제약 설계가 필요해지고, DB 의존적인 구현 복잡도도 올라갑니다.

#### 3) 분산 락 적용

Redis 같은 외부 락도 방법이지만, 현재 규모에서는 오버엔지니어링에 가깝다고 판단했습니다.
우선은 트랜잭션과 DB 락으로 해결 가능한 범위였습니다.

## 5. 검증 방법

`MissionVerificationConcurrencyTest`를 추가해 실제로 동시 요청 상황을 재현했습니다.

테스트 시나리오는 다음과 같습니다.

1. 같은 사용자와 같은 미션을 준비합니다.
2. 스레드 2개가 동시에 제출 API 서비스 로직을 호출합니다.
3. 결과를 수집해 성공/실패 개수를 검증합니다.

기대 결과는 다음과 같습니다.

- 성공 1건
- 실패 1건
- 실패 원인은 `MISSION_UNDER_REVIEW`
- DB 저장 건수는 최종 1건

## 6. 이번 작업으로 증명한 것

이번 테스트가 증명한 것은 "성능 향상"이 아니라 "동시 요청에서도 정합성이 깨지지 않는다"는 점입니다.

즉, 이번 작업의 핵심 성과는 처리 속도 개선이 아니라 다음입니다.

- 중복 제출 방지 규칙 보장
- 같은 사용자 동시 요청에 대한 일관된 결과 보장
- 검수 대기 데이터의 무결성 확보

이번 작업을 통해 미션 인증 제출 API는 같은 사용자의 동시 요청 상황에서도 비즈니스 규칙을 일관되게 지키도록 보완되었습니다. 단순히 예외를 막는 수준이 아니라, 검수 대기 데이터가 중복 생성되지 않도록 서비스 정합성을 트랜잭션 단위에서 보장했다는 점에 의미가 있습니다.
